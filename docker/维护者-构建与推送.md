# 维护者：镜像构建与推送（以及"别让老版本占着仓库"）

> 这份文档给**发版的人**看。普通部署用户不需要它（看 `使用说明.md` / `从镜像仓库部署.md`）。

## 一、仓库里一共有 4 个镜像，各有各的用处

| 镜像 | 是什么 | 变了就要重推吗 |
|---|---|---|
| `.../multimodal-app:latest` | 应用本体（CPU 版 torch） | **改一行代码就要** |
| `.../multimodal-app:gpu` | 应用本体（CUDA 版 torch） | 同上 |
| `.../multimodal-ollama:latest` | Ollama 运行时（打好的 `ollama` 镜像 + 脚本） | Ollama 版本没变就不用 |
| `.../multimodal-models:latest` | **数据镜像**：`/models` 下的全部模型，供"从镜像仓库部署"提取 | **换了任何模型就要** |
| `.../multimodal-deploy:latest` | 部署套件（`/deploy` 下的 `一键部署.bat`、`compose.yml`、说明文档…） | 改了部署脚本/文档就要 |

⚠️ **最容易漏的是后两个**：
- 只推 `multimodal-app` → 别人从镜像仓库部署时，**拿到的还是旧模型**（例如 sd-turbo 而不是 SDXL），
  界面看起来正常，但画图质量对不上 —— 这种"代码是新的、模型是旧的"最难排查。
- 只推 app 不推 `multimodal-deploy` → 别人 `docker run` 取出来的还是老版 `一键部署.bat`。

## 二、构建

```bash
cd <源码目录>          # 例如 D:\local-multimodal-src

# 应用（CPU）
docker build -f docker/Dockerfile.app -t local-multimodal-app:latest .

# 应用（GPU，CUDA 版 torch；构建慢，装 torch 那层几分钟）
docker build -f docker/Dockerfile.app \
  --build-arg TORCH_INDEX=https://download.pytorch.org/whl/cu130 \
  -t local-multimodal-app:gpu .
```

数据镜像（`FROM scratch` + 复制 `/models`，最小）：

```bash
cd /e/本地多模态助手-Docker
printf 'FROM scratch\nCOPY models /models\n' > /tmp/Dockerfile.models
docker build -f /tmp/Dockerfile.models -t local-multimodal-models:latest .
```

部署套件（把要分发的脚本放进 `/deploy`）—— **不要手抄文件，跑脚本**：

```bash
cd /e/本地多模态助手-Docker
python make_deploy_kit.py          # 从包根生成 _deploy-kit/（含 data/config.json）
docker build -f _deploy-kit/Dockerfile -t local-multimodal-deploy:latest _deploy-kit
```

> ⚠️ **部署脚本有"三份同名副本"，这是最容易各改各的地方**（2026-09-27 实测踩到）：
>
> | 副本 | 给谁用 |
> |---|---|
> | 包根目录 `一键部署.bat` / `使用说明.md` / `从镜像仓库部署.md` | 用户直接双击/阅读 |
> | `build/docker/` 下同名文件 | 从包内 `docker build -f docker/Dockerfile.app .` 的构建上下文 |
> | `_deploy-kit/` → 打成 `multimodal-deploy:latest` | "从镜像仓库部署"的人 `docker run` 取出来用 |
>
> 那次只有包根改了"约 50GB / 58GB"，套件镜像里还是"18GB / 27GB"，
> 而且 `data/config.json` 压根没进套件 —— 用户照着文档去找，找不到。
> ⇒ **改完包根必须 `python make_deploy_kit.py` 再重建套件**，然后 `docker pull` 回来核对。
>
> 另外：`.bat` 是 **GBK + CRLF**，用普通编辑器改会把中文写成 UTF-8 → cmd 里乱码。
> 要改就用 Python 显式 `decode('gbk')` / `encode('gbk')`。
>
> `data/config.json` 是**配置样本**（给用户看的"可调项清单"），真源是
> `backend/config.py` 的 `DEFAULT_CONFIG`，由 `docker/gen_sample_config.py` 派生：
>
> ```bash
> python docker/gen_sample_config.py            # 写仓库 docker/data/config.json + 交付包
> ```
>
> ⚠️ `docker/data/` 在 `.gitignore` 里，所以**样本本身不进版本库**，别指望 diff 能发现它过期 ——
> 改了 `DEFAULT_CONFIG` 就跑一次上面的脚本。以前没人管它，于是模型名一直停在
> `qwen3-vl:8b` / `qwen2.5-coder:14b`，`num_ctx` 写着 24576，还漏了 7 个新增键。

## 三、推送

```bash
REG=ccr.ccs.tencentyun.com/bendiai
for t in latest gpu; do
  docker tag local-multimodal-app:$t $REG/multimodal-app:$t
  docker push $REG/multimodal-app:$t
done
docker tag local-multimodal-models:latest   $REG/multimodal-models:latest   && docker push $REG/multimodal-models:latest
docker tag local-multimodal-deploy:latest   $REG/multimodal-deploy:latest   && docker push $REG/multimodal-deploy:latest
```

### 推完必须**拉回来比对**（这是唯一能证明"推上去的就是本地的"的办法）

```bash
docker pull --quiet $REG/multimodal-app:latest >/dev/null
docker image inspect -f '{{.Id}}' $REG/multimodal-app:latest   # 应与本地构建的 ID 完全一致
```

> 光看 `docker push` 输出"digest: sha256:…"不够 —— 那只是**上传摘要**。
> 真正要对的是**本地镜像 ID == 拉回来后的镜像 ID**。

## 四、"老版本占着仓库空间"怎么处理

先说清楚一个事实：**`docker push` 覆盖同名 tag 之后，被替换掉的旧层在仓库里是"无 tag 的悬空数据"**，
命令行（`docker` CLI）**删不掉**它们 —— Registry v2 API 的 `DELETE` 需要管理凭据。
所以分工是：

| 对象 | 能做什么 | 怎么做 |
|---|---|---|
| **仓库里的悬空层** | 在 **CCR 控制台**做垃圾回收 / 删除仓库 | 腾讯云 → 容器镜像服务 → 命名空间 `bendiai` → 选仓库 → 清理无用版本 |
| **仓库里多余的 tag** | 保留约定：只留 `latest` / `gpu` | 同上；**不要**每次发版都推 `v1`、`v2`、`20260926` 这类日期 tag，否则 tag 会越堆越多 |
| **不再需要的整个仓库** | 控制台删除该仓库 | 例如某个功能废弃后它的镜像仓库可以整个删掉 |
| **本机 Docker** | 清悬空镜像 + 构建缓存（**这个能真正做到，而且效果最大**） | 见下 |

本机清理（安全、只删悬空与缓存，不动在用镜像）：

```bash
docker image prune -f          # 悬空镜像（被替换掉的旧构建层）
docker builder prune -f        # 构建缓存（BuildKit）
docker system df               # 看回收了多少
```

⚠️ **不要**用 `docker system prune -a` —— 那会把你**所有**没在运行的镜像（包含离线 tar 的源镜像、
`local-multimodal-models` 这种大镜像）一起删掉，重做一次要几十分钟。
发版前用不带 `-a` 的两个 prune 就够了。

## 五、发版检查清单

- [ ] 源码改动全部提交并推到 GitHub（`git status --porcelain` 为空）
- [ ] 离线交付包 `build/` 里的源码已同步（`diff -rq 源码/backend 交付包/build/backend` 无差异）
- [ ] 构建上下文里没有 `__pycache__` / `*.pyc` / `*.bak`（`.dockerignore` 的 `**/` 前缀已覆盖）
- [ ] 两个 app 镜像都重建（**别只重建 CPU**，GPU 版才是绝大多数用户跑的）
- [ ] 镜像里能查到本次新增的关键函数（`docker run --rm --entrypoint grep <tag> -c xxx /opt/app/backend/...`）
- [ ] 镜像里没有垃圾文件：
      `docker run --rm --entrypoint sh <tag> -c "find /opt/app \( -name '__pycache__' -o -name '*.pyc' -o -name '*.bak*' \) | wc -l"` → **0**
- [ ] `docker save` 重打 tar → `make_manifest.py` 重生成清单 → 校验通过
- [ ] **tar 里的代码与当前源码逐文件比 sha256**（比 ID 会误判：换 pip/torch 源重建 ID 就变）
      ```bash
      python scripts/check_tar_content.py "E:/本地多模态助手-Docker/images/local-multimodal-app.tar"
      ```
      → 每行 `[OK]`、末行"一致 ✅"。改过 `backend/` 或 `frontend/` 后旧 tar 一定不过，重打即可。
- [ ] **三份部署脚本副本已同步**：包根 == `build/docker/` == `_deploy-kit/`
      （`python make_deploy_kit.py` 后 `diff -rq <源码>/docker <包>/build/docker`）
- [ ] `data/config.json` 与 `backend/config.py` 的 `DEFAULT_CONFIG` 键一致（33 个键）
- [ ] 四个镜像按需推完（app 必推；**动了模型务必推 multimodal-models**；动了部署脚本/文档务必推 multimodal-deploy）
- [ ] 每个推完的都 `docker pull` 回来比对 ID
- [ ] 本机 `docker image prune -f` + `docker builder prune -f`
