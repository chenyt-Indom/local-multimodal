# 本地多模态助手 · Docker 一键部署包

一套可以在**任意一台装有 Docker 的电脑**上直接展开使用的离线部署包。
支持对话、看图、联网搜索、联网搜图、图片库、长期记忆、多会话、文生图与高清超分。

---

## 一、最少需要做什么

1. 把整个 `local-multimodal-docker` 文件夹拷到目标电脑（U 盘 / 移动硬盘 / 网络共享均可）
2. 目标电脑装好 **Docker Desktop** 并启动它（[下载地址](https://www.docker.com/products/docker-desktop/)）
3. 双击 **`一键部署.bat`**
4. 等它自己跑完，浏览器会自动打开 <http://127.0.0.1:8000>

脚本会自动完成：识别显卡 → 选择版本 → 导入镜像 → 启动容器 → 打开界面。

---

## 二、目录说明

```
local-multimodal-docker\
├── 一键部署.bat          ← 双击这个
├── 停止运行.bat          ← 停止（数据保留）
├── 查看状态.bat          ← 看容器状态与日志
├── 完全卸载.bat          ← 删除容器/镜像/数据
├── 使用说明.md           ← 本文档
│
├── compose.full.yml      ← 完整版编排
├── compose.lite.yml      ← 精简版编排
├── compose.full.gpu.yml  ← 完整版显卡加速（有 NVIDIA 显卡时自动叠加）
├── compose.lite.gpu.yml  ← 精简版显卡加速
├── ollama-init.sh        ← 精简版首次自动下载模型
│
├── images\               ← 离线镜像包（docker save 导出的 tar）【运行必需】
├── data\                 ← 【你的数据】记忆库/会话/图片库/日志
├── ollama-models\        ← 精简版的对话模型缓存（只有精简版用得到）
└── build\                ← 构建上下文（源码 + 模型，仅「重新构建镜像」时需要）
```

> **重要**：`data\` 就是你的全部个人数据。想换电脑时，只要把它一起拷走，记忆和历史对话就都跟着走。

### 只想拷给别人用？可以精简

| 目录 | 体积 | 能否删除 |
|---|---|---|
| `images\` | 约 12.7 GB | **不能删**，运行时靠它导入镜像 |
| `data\` | 你的数据 | 建议一起带走 |
| `build\` | 约 10 GB | **可以删**，删了之后无法重新构建镜像，但运行照常 |
| `ollama-models\` | 0～6 GB | 精简版用；完整版用不到，可删 |

也就是说：**只想拿去用，`images\` + 脚本 + `data\` 就够了**，约 13 GB。

## 三、两个版本怎么选

| | 完整版 full | 精简版 lite |
|---|---|---|
| 镜像体积 | 约 12 GB | 约 300 MB |
| 是否联网 | **完全离线**，装好就能用 | 首次需联网下载对话模型（约 6 GB） |
| 内含模型 | Qwen3-VL 对话模型 + SD 绘图模型 + 超分模型 | 无（模型存到 `ollama-models\`） |
| 适用场景 | 内网机器、无网环境、要画图 | 网络通畅、想快速铺开 |

`一键部署.bat` 会**自动选择**：`images\` 里有完整版离线包就用完整版，否则用精简版。
想手动指定：

```bat
一键部署.bat full
一键部署.bat lite
```

## 四、显卡会自动适配

脚本会检测 `nvidia-smi`：

- **检测到 NVIDIA 显卡** → 自动叠加 `compose.*.gpu.yml`，对话推理走显卡（快很多）
- **没检测到** → 走 CPU，功能完全一样，只是慢一些

### 想让「画图」也吃显卡

默认镜像里装的是 **CPU 版 torch**（为了通用性）。如果希望 Stable Diffusion 也用显卡，用 CUDA 版 torch 重建完整版镜像：

```bat
cd build
docker build -f docker/Dockerfile.full ^
  --build-context models=./models ^
  --build-arg TORCH_INDEX=https://download.pytorch.org/whl/cu124 ^
  -t local-multimodal-full:latest .
```

> 注意：重建后需要重新 `docker save` 导出，才能带到别的机器用。

## 五、常用操作

```bat
:: 查看实时日志
docker logs -f mm-app

:: 进入容器
docker exec -it mm-app bash

:: 精简版手动补下模型
docker exec -it mm-ollama ollama pull qwen3-vl:8b

:: 修改界面端口（默认 8000）→ 编辑 compose.*.yml 的 ports 段
```

```bat

xcopy /E /I data  D:\备份\multimodal-data
```

## 六、容器环境下的功能差异

| 功能 | 完整版 | 精简版 | 说明 |
|---|---|---|---|
| 对话 / 看图 | ✅ | ✅ | 需要对话模型 |
| 联网搜索 / 联网搜图 | ✅ | ✅ | 需要外网 |
| 长期记忆 / 多会话 / 图片库 | ✅ | ✅ | 数据存在 `data\` |
| 文生图 / 图片微改 | ✅ | ❌ | 精简版不含 torch 与绘图模型 |
| 高清超分 | ✅ | ❌ | 同上 |
| **语音输入（唤醒词）** | ❌ | ❌ | 容器拿不到麦克风，容器内一律不可用 |

> 语音输入在宿主机源码方式运行时才可用；Docker 里没有音频设备，属于平台限制。

## 七、常见问题

**Q：双击后提示「未检测到可用的 Docker 引擎」**
Docker Desktop 没启动。先打开它，等右下角鲸鱼图标变成稳定状态再重试。

**Q：部署完成但界面打开是空白 / 打不开**
运行 `查看状态.bat` 看日志。多半是端口 8000 被占用，改 `compose.*.yml` 里的 `ports` 为 `"8001:8000"` 再重新部署。

**Q：精简版一直转圈，说模型没就绪**
首次下载 6GB 模型需要时间。`查看状态.bat` 里能看到进度。模型下完就永久存在 `ollama-models\`，之后启动都是秒开。

**Q：换了台电脑，历史对话还在吗**
把 `data\` 一起拷过去就还在。这是刻意设计成独立目录的。

**Q：显卡明明有，为什么还是慢**
先自检容器能不能用显卡：
```bat
docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi
```
跑不通说明是宿主机驱动或 Docker 的 GPU 透传没配好（Linux 需要 `nvidia-container-toolkit`；Windows 需要 WSL2 后端 + 最新 NVIDIA 驱动）。

## 八、技术说明（给维护者）

- 镜像间的路径约定：
  - 代码 → `/opt/app`（`backend/`、`frontend/`）
  - 模型 → 对话模型 `/root/.ollama/models`，绘图模型 `/opt/app/sd_model`，超分 `/opt/app/esrgan`
  - 数据 → `/data`（由 `MM_DATA_DIR` 环境变量指定，见 `backend/config.py`）
- 关键环境变量：
  | 变量 | 作用 |
  |---|---|
  | `MM_DATA_DIR` | 可写数据根目录（记忆库/会话/图片库/日志） |
  | `MM_OLLAMA_URL` | Ollama 服务地址（精简版指向 `http://ollama:11434`） |
  | `MM_MODEL` | 默认模型名 |
  | `SD_MODEL_DIR` | 绘图模型目录 |
  | `ESRGAN_MODEL` | 超分模型文件 |
- 模型体积大，作为**独立构建上下文**传入（`--build-context models=./models`），
  这样精简版构建不会白白传输 GB 级数据。
- 容器内应用用 `uvicorn` 直接起，多模态推理需要较大共享内存，
  完整版 compose 里设了 `shm_size: 2gb`。
