# 本地多模态助手 · Docker 一键部署包

可以在**任意一台装有 Docker 的电脑**上直接展开使用。
含对话、看图、联网搜索、联网搜图、图片库、长期记忆、多会话、文生图、高清超分、视频抽帧。

---

## 一、最少需要做什么

1. 把整个 `本地多模态助手-Docker` 文件夹拷到目标电脑（U 盘 / 移动硬盘 / 网络共享）
2. 目标电脑装好 **Docker Desktop** 并启动它（[下载](https://www.docker.com/products/docker-desktop/)）
3. 双击 **`一键部署.bat`**
4. 等它自己跑完，浏览器自动打开 <http://127.0.0.1:8000>

脚本会自动完成：识别显卡 → 选择 Ollama 模式 → 导入镜像 → 启动容器 → 等就绪 → 开浏览器。

```

├── 一键部署.bat          ← 双击这个
├── 校验安装包.bat        ← 拷过来之后先双击这个，自检有没有漏文件
├── 停止运行.bat          ← 停止（数据保留）
├── 查看状态.bat          ← 看容器状态与日志

├── 使用说明.md           ← 本文档
├── 安装包清单.json       ← 校验用的清单（由打包时生成，别删）
│
├── compose.yml           ← 主编排（app + 可选 Ollama）
├── compose.gpu.yml       ← 显卡加速覆盖（有 NVIDIA 卡时自动叠加）
├── open-folder-agent.ps1 ← 「打开文件夹」小助手（由部署脚本自动拉起）
├── .env                  ← 由一键部署脚本自动生成
│
├── installers\           ← 安装程序 ★新机器没装 Docker 时要用
│   └── DockerDesktopInstaller.exe    Docker Desktop 安装程序（约 599 MB）
├── images\               ← 离线镜像包 ★运行必需
│   ├── local-multimodal-app.tar      应用镜像 · CPU 版
│   ├── local-multimodal-app-gpu.tar  应用镜像 · CUDA 版（有 N 卡时自动选用）
│   └── local-multimodal-ollama.tar   Ollama 引擎
├── models\               ← 模型权重 ★运行必需（不在镜像里，避免存两份）
│   ├── ollama\           对话模型 qwen3-vl:8b（5.8GB）+ 代码模型 qwen2.5-coder:14b（8.6GB）
│   ├── sd-turbo\         绘图模型
│   └── esrgan\           超分模型
├── data\                 ← 【你的数据】记忆库/会话/图片库/生成文库/日志
└── build\                ← 源码与 Dockerfile（仅重新构建镜像时需要，可删）
```

> ⚠️ **`models\` 是模型真正所在的地方，不在任何 tar 里。**
> 只拷 `images\*.tar` 而不拷 `models\`，容器起来会**没有模型**（得重新下载 15GB）。
> 这也是为什么提供了「校验安装包.bat」——落地先自检一遍最省事。

> **`data\` 就是你的全部个人数据**。换电脑时把它一起拷走，记忆和历史对话就都跟着走。

### 只想拷给别人用？

| 目录 | 体积 | 能否删 |
|---|---|---|
| `images\` | 约 7 GB（应用 0.5 + GPU 版 3 + Ollama 3.5） | **不能删**；不用显卡的机器可删 GPU 版那一份 |
| `models\` | 约 19 GB（对话 5.8 + **代码 8.6** + 绘图 4 + 超分 0.06） | **不能删** |
| `installers\` | 约 599 MB（Docker Desktop 安装程序） | 目标机器**已装好 Docker** 就可以删 |
| `data\` | 很小（干净的初始配置） | 想延续**记忆和历史对话**就带上；不想要就删掉（会自动新建） |
| `build\` | 约 220 MB | 可以删，删了就无法重新构建镜像 |

> `build\` 里那 220 MB 有 219 MB 是 `docker\vendor-assets\`（构建期用的离线资源）。
> **当前版本构建用不到它** —— 只在你想把「开发台」加回来时才需要（见 `vendor-assets\README.md`）。
> 想给包瘦身，删掉 `build\docker\vendor-assets\` 即可，**不影响部署与构建**。

**合计约 27 GB**，其中 `images\` + `models\` 是运行必需的。

### 搬到另一台电脑（五步）

> **已实测**：在一台**只装了 Docker Desktop** 的电脑上可以一键跑起来。
> 唯一的硬性前提就是 Docker Desktop，其余全是拷贝 + 双击。
>
> 最近一次验证做到这个程度：把本机镜像**全部删光**（完全等同新机器）、
> 强制走自带模式，双击 `一键部署.bat` → 自动导入 7 GB 镜像 → 两个容器健康起来
> → 对话、写代码、生成文库、导出 Word 逐项跑通。

**第 0 步｜先看新电脑有没有空间**

Docker 会把镜像解压到它自己的数据盘 —— **Windows 上默认是 C 盘**
（`%LOCALAPPDATA%\Docker\wsl\disk\docker_data.vhdx`）。

| 装什么 | Docker 数据盘要占 |
|---|---|
| 应用镜像（GPU 版） | 约 10 GB |
| Ollama 引擎 | 约 9 GB |
| **合计** | **约 20 GB**（安全起见留 30 GB） |

> C 盘不够的话：Docker Desktop → Settings → Resources → Advanced →
> **Disk image location** 改到空间大的盘，再继续第 1 步。
> 另外**包本身还要 26 GB**（放在哪都行，不必和 Docker 同一个盘）。

**第 1 步｜新电脑安装 Docker Desktop（包里已自带安装程序）**

这是**唯一需要手动安装**的东西，而且**安装程序就在包里**：

```
installers\DockerDesktopInstaller.exe      （约 599 MB）
```

双击它，安装时保持默认选项即可 —— ⚠️ **务必勾选「Use WSL 2 instead of Hyper-V」**
（现在默认就是它，别手动改）。装完可能需要**重启一次**，然后启动 Docker Desktop，
等任务栏鲸鱼图标不再转动（引擎就绪）。

> 已经装过 Docker 的机器跳过这步；**不需要装 Python，也不需要装 Ollama。**
> 如果别的机器上想手动下载：https://www.docker.com/products/docker-desktop/

> 💡 忘装直接双击 `一键部署.bat` 也没关系 —— 它会检测到并**引导你打开这个安装程序**，
> 装完再双击一次脚本就能接着部署。

**第 2 步｜把整个文件夹拷过去**

> ⚠️ **最省事的做法：整个文件夹一起拷**（别只挑几个子目录）。
> 真正必需的只有 `images\` + `models\` + 那几个脚本和 yml，
> 但漏拷 `models\` 是最常见的翻车方式 —— 容器能起来，但**里面没有模型**。

用移动硬盘最快，合计约 **27 GB**：

| 拷什么 | 体积 | 说明 |
|---|---|---|
| `images\` | 7.1 GB | 离线镜像，**必需** |
| `models\` | 19 GB | 模型权重（对话 + 代码 + 绘图），**必需** |
| `installers\` | 599 MB | Docker 安装程序；目标机已装 Docker 可不带 |
| 脚本 + `compose.yml` + `compose.gpu.yml` + `open-folder-agent.ps1` + 说明 + `安装包清单.json` | 很小 | **必需** |
| `data\` | 很小 | 想延续**记忆和历史对话**就带上；不想要就删掉（会自动新建） |
| `build\` | 221 MB | 可以不带（只在需要重新构建镜像时用） |

目录名用中文没问题（已验证）；放在哪个盘、叫什么名字都行 ——
`.env` 会在部署时按**实际位置自动重新生成**，不会残留旧电脑的路径。

**第 2.5 步｜拷完先自检一遍（强烈建议，10 秒）**

双击 **`校验安装包.bat`**。它会逐项核对：

```
  [OK]   images\local-multimodal-app.tar   (522.3 MB)
  [OK]   models\ollama   9 个文件，15.0 GB
  [OK]   Docker 引擎可用（Server 29.7.2）
  ...
  校验通过！共 12 项正常。
```

26 GB 的拷贝最怕**静默漏文件**（U 盘拔早了、中途中断）。与其等到部署时报错，
不如先花 10 秒确认。它还会顺带告诉你：磁盘够不够、Docker 装了没、有没有 N 卡。

> 想更严格（比对 SHA256，能查出静默损坏，但要跑几分钟）：
> 在该目录打开 PowerShell 执行 `.\校验安装包.ps1 -Full`

**第 3 步｜双击 `一键部署.bat`**

剩下全自动，不用管。脚本会依次：

1. 检查 Docker 引擎是否在跑
2. 看有没有 NVIDIA 显卡（有就启用 GPU，并挑 CUDA 版镜像）
3. 探测本机有没有 Ollama（没有就用包里的，零下载）
4. 从 `images\` 导入镜像
5. 启动服务，等它就绪，然后**自动打开浏览器**

**第 4 步｜等它跑完**

| 阶段 | 大概耗时 |
|---|---|
| 导入镜像（首次才会做） | 1–3 分钟 |
| 启动容器 | 10–20 秒 |
| 打开页面后**第一次提问** | 首次要加载模型，约 30 秒 |

看到 `部署完成！正在打开浏览器：http://127.0.0.1:8000` 就成了。
以后再用就快得多（镜像已导入，只启动容器）。

**日常怎么用**

- 再看一次状态：`查看状态.bat`（含日志、磁盘占用）
- 用完停止：`停止运行.bat`（数据保留）
- 彻底不要了：`完全卸载.bat`

> **目标电脑上不需要装 Ollama。**
> 脚本探测不到本机 Ollama 时会自动改用**自带模式**，直接使用 `models\ollama\` 里的模型
> （`qwen3-vl:8b` 已随包提供，零下载）。

### 目标电脑的硬件要求

| | 要求 | 说明 |
|---|---|---|
| 系统 | Windows 10/11（64 位） | 部署脚本是 Windows 批处理；WSL2 由 Docker Desktop 自动配好 |
| 显卡 | NVIDIA（**强烈建议**） | 有则自动启用 GPU 加速。**实测差距极大**，见下表 |
| 内存 | 建议 ≥ 16 GB | 两个模型加起来约 15 GB；纯 CPU 跑建议 32 GB |
| 硬盘 | 包 27 GB + Docker 数据盘 30 GB | 两处都要留够（Docker 默认用 C 盘，可在设置里改） |
| 端口 | 8000 空闲 | 被别的程序占用会启动失败 |

**⚠️ 显卡这事必须说清楚**（同一台机器实测，跑 `qwen2.5-coder:14b`）：

| | 生成速度 | 一句话的等待 |
|---|---|---|
| **有 N 卡（GPU）** | **25.6 字/秒** | 几秒 |
| 只有 CPU | **约 0.4 字/秒** | **好几分钟** |

CPU 模式**功能是全的**（对话、写代码、画图都能跑），但那个速度基本没法日常用。
脚本检测不到 N 卡时会明确警告你，并让你确认是否继续。

## 三、两种 Ollama 模式（关键）

Ollama 是"跑对话模型的引擎"。它有两种放法，`一键部署.bat` 会**自动选**：

| | ① 直连模式（默认） | ② 自带模式 |
|---|---|---|
| 用哪个 Ollama | **宿主机已经装好的** | 容器里再跑一个 |
| 需要下载吗 | **完全不用** | 不用（引擎镜像 + 两个模型都已备好） |
| 启动速度 | 几秒 | 首次拉镜像较久 |
| 前提 | 目标机器已装 Ollama 并运行 | 只需 Docker |
| 目标机器适合 | 日常自用、已装过 Ollama | 全新机器、想彻底自包含 |

手动指定：
```bat
一键部署.bat            :: 自动判断
一键部署.bat direct     :: 强制直连宿主机
一键部署.bat bundled    :: 强制容器自带
```

### 直连模式用的是什么？

容器通过 `host.docker.internal` 连宿主机的 `11434` 端口 —— **模型一字节都不用下载**，
因为你本机 `C:\Users\<你>\.ollama\models` 里已经有了（本包 `models\ollama` 是它的副本，
含对话模型和代码模型）。

> Linux 上如果连不上，是因为 Ollama 默认只监听 127.0.0.1。改成：
> `sudo systemctl edit ollama` 加 `Environment="OLLAMA_HOST=0.0.0.0"` 后重启。

### 自带模式怎么准备镜像？

### 包里带了哪些模型（都是离线的，零下载）

| 模型 | 干什么用 | 体积 | 放在哪 |
|---|---|---|---|
| `qwen3-vl:8b` | 对话、看图、写文档、图像理解 | 5.8 GB | `models\ollama\` |
| `qwen2.5-coder:14b` | **写代码**（非思考型，快且稳） | 8.6 GB | `models\ollama\` |
| `sd-turbo` | 文生图 / 图片微改 | 4 GB | `models\sd-turbo\` |
| `esrgan` | 图片超分 | 64 MB | `models\esrgan\` |

> 两个 Ollama 模型都已按 **sha256 逐个校验过**，换机器后不会出现"模型加载失败"。
> 自带模式下容器直接用 `models\ollama\`，直连模式下用你本机 `~/.ollama/models` ——
> 两种情况都**不需要联网**。

离线包 `images\local-multimodal-ollama.tar` 已经准备好了，直接导入即可。
如果要从网上拉，国内建议走镜像源：
```bat
docker pull docker.1ms.run/ollama/ollama:latest
docker tag  docker.1ms.run/ollama/ollama:latest local-multimodal-ollama:latest
docker save local-multimodal-ollama:latest -o images\local-multimodal-ollama.tar
```

## 四、显卡会自动适配

脚本会检测 `nvidia-smi`，据此自动决定两件事：

- **用哪个应用镜像** —— 有 N 卡且包里有 GPU 镜像 → 用 **CUDA 版**；否则用 **CPU 版**
- **要不要叠加 `compose.gpu.yml`** —— 有 N 卡就叠加，让容器能拿到显卡

> **对话 / 看图**由 Ollama 负责 —— 只要用脚本启动（会自动叠加 GPU 编排），
> 这部分本来就在用显卡，无需额外操作。
> 下面讲的都是**绘图**（文生图 / 图片微改），它跑在应用容器里，另有一套要求。

### 包里自带两个镜像，脚本自动挑

| 镜像 | tar 文件 | tar 体积 | 装什么 torch | 用来干什么 |
|---|---|---|---|---|
| CPU 版 | `images\local-multimodal-app.tar` | 约 0.5 GB | `2.14.0+cpu` | 任何机器都能跑，绘图较慢 |
| **CUDA 版** | `images\local-multimodal-app-gpu.tar` | 约 3 GB | `2.14.0+cu130` | **绘图走显卡** |

两者**功能完全相同**，区别只在 torch 是怎么编译的。

- 检测到 N 卡 → 自动用 CUDA 版 → 文生图**首张约 18 秒**（含加载模型），
  之后**约 0.5 秒一张**（CPU 版实测约 20 秒一张）
- 没有 N 卡 → 自动用 CPU 版 → Docker 里**少占约 7 GB**（10 GB → 2.4 GB）

> **只想给没有显卡的电脑用？** 直接把 `images\local-multimodal-app-gpu.tar`
> 删掉就行 —— 脚本找不到它会自动退回 CPU 版，不会报错。

### 想手动指定

改 `.env` 里的一行即可（注意脚本每次运行会重写 `.env`；
想长期固定就改 `compose.yml` 里 `APP_IMAGE` 的默认值）：

```
APP_IMAGE=local-multimodal-app:gpu      # CUDA 版
APP_IMAGE=local-multimodal-app:latest   # CPU 版
```

### 自己重新构建 CUDA 版（可选）

```bat
cd build
docker build -f docker/Dockerfile.app ^
  --build-arg TORCH_INDEX=https://download.pytorch.org/whl/cu130 ^
  -t local-multimodal-app:gpu .
docker save local-multimodal-app:gpu -o ..\images\local-multimodal-app-gpu.tar
```

#### ⚠️ CUDA 版本别选错

torch 轮子是按 GPU **算力架构**编译的，选错会在推理时报
`no kernel image is available for execution on the device`：

| 显卡 | 架构 | 该用哪个 |
|---|---|---|
| RTX 50 系（5070 / 5080 / 5090…） | Blackwell / sm_120 | **cu130**（cu124 **不行**） |
| RTX 40 系 | Ada / sm_89 | cu124 / cu128 / cu130 |
| RTX 30 系 | Ampere / sm_86 | cu124 / cu128 / cu130 |

不确定就用 **cu130**（向下兼容较老的架构）。
自查命令：装好后进容器执行
`python3 -c "import torch;print(torch.cuda.get_arch_list())"`，
列表里应包含你显卡的架构（5070 Ti 是 `sm_120`）。

> 重建后镜像会从约 2.4 GB 涨到约 5~6 GB（CUDA 运行时要打进去）。
> 想退回省空间的 CPU 版：把 `--build-arg` 去掉重新构建即可。
> 构建前建议先备份：`docker tag local-multimodal-app:latest local-multimodal-app:cpu`

### 怎么确认现在跑的是 CPU 还是 GPU

界面顶部标题栏右侧有一个徽章，**点它就能切换**：

| 徽章 | 含义 |
|---|---|
| 🖥 **CPU 模式** | 绘图（文生图 / 图片微改）用 CPU，单张约 20 秒 |
| ⚡ **GPU 加速（显卡名）** | 绘图用显卡 |

点开后有三个选项，当前选择标有「当前」：

| 选项 | 说明 |
|---|---|
| 🔍 **自动（推荐）** | **程序自己探测**：有可用显卡就用显卡，没有就 CPU。这是默认值 |
| ⚡ **GPU 加速** | 强制用显卡（探测不到会拒绝切换，不会静默回退） |
| 🖥 **CPU 模式** | 强制用 CPU（机器有显卡时，可以主动让出显存给别的程序） |

> **程序本身就有主动检测能力**，默认就走「自动」——
> 装好显卡驱动、让容器能拿到显卡之后，**不需要手动切换**，程序自己就会用上。
> 手动切换只是"强制覆盖"用的（比如想省显存、或想复现某个问题）。

### 切换时会真的校验，不是只改个显示

切换不是简单翻个开关，后端会依次做两件事：

1. **在目标设备上跑一次真实矩阵运算** —— 只查 `cuda.is_available()` 是不够的，
   那个为真但一算就崩（显存被占满、驱动不匹配、容器透传不完整）很常见；
2. **把绘图引擎实际加载到该设备上** —— 这才是"确实能跑"的证明
   （设备能用不代表这个模型装得上去，显存不够、权重精度不兼容会在这步失败）。

> 如果选到的设备**和当前已经加载的一致**（例如在「自动」和「GPU」之间来回点，
> 而实际都是 GPU），会直接沿用已加载的引擎，**不重复加载**，瞬间完成。

两步都通过才显示「✅ 已成功切换」；任一步失败会显示
**❌ 失败原因 + 当前实际仍是哪个模式**，并且**不会真的改掉设置**
（避免切换失败后每次绘图都撞同一个错）。

切换期间界面会提示「正在校验」，一般几秒到几十秒（要等引擎加载）。

也可直接用接口确认或切换：

```bat
curl http://127.0.0.1:8000/api/t2i/capability
curl -X POST http://127.0.0.1:8000/api/t2i/device ^
     -H "Content-Type: application/json" -d "{\"mode\":\"gpu\"}"
```

`capability` 返回里的 `kind` 就是当前设备（`cpu` / `gpu`）。

### 切换 GPU 失败？看原因对症下药

| 提示原因 | 说明与解决 |
|---|---|
| 装的是 **CPU 版 torch** | 说明当前用的是 CPU 版镜像。正常情况下有 N 卡时脚本会自动选 CUDA 版；若没选上，多半是 `images\local-multimodal-app-gpu.tar` 不在（被删了或没拷过来），或 `.env` 里的 `APP_IMAGE` 被改过。见第四节 |
| **检测不到任何显卡设备** | torch 是 CUDA 版，但容器没拿到显卡。用 `docker compose -f compose.yml -f compose.gpu.yml up -d` 启动（`一键部署.bat` 会自动加） |
| **绘图引擎加载失败（显存不足等）** | 显卡可用但装不下模型；先关掉占显存的其他程序，或切回 CPU |

> **说明**：文生图和图片微改**共用同一个 torch 环境**，所以两者的设备一定相同 ——
> 要么都是 CPU，要么都是 GPU，不会一个走显卡一个走 CPU。
> 区别只在于：微改要读一张参考图，耗时略长一点。

## 七、常见问题

**Q：提示「未检测到可用的 Docker 引擎」**
Docker Desktop 没启动。先打开它，等右下角鲸鱼图标稳定后再重试。

**Q：部署完成但页面打不开**
运行 `查看状态.bat` 看日志。多半是 8000 端口被占用，改 `.env` 的 `APP_PORT` 后重新部署。

**Q：直连模式下报「无法连接 Ollama」**
本机 Ollama 没在运行。启动它（开始菜单搜 Ollama），或改用自带模式 `一键部署.bat bundled`。

**Q：不想用本机的 Ollama**
用 `一键部署.bat bundled`，模型已在 `models\ollama` 里，容器直接用，不用重新下载。

**Q：换台电脑，聊天记录还在吗**
把 `data\` 一起拷过去就还在。

**Q：点「打开文件夹」没反应 / 只显示了一串路径**
说明宿主机上的小助手没在运行。重新运行一次「一键部署.bat」即可把它拉起来；
也可以用「查看状态.bat」看它是否在运行。
小助手是你电脑上一个隐藏的后台进程（`open-folder-agent.ps1`），
只做一件事：盯着 `data\` 里的一个请求文件，看到就帮你弹出对应的文件夹。
容器本身打不开 Windows 的资源管理器，所以需要它代劳。停止程序时会被一起关掉。

**Q：图片库的「📂 文件夹」按钮打开的是哪个目录？**
是 `data\image_library\` —— 和图片实际保存的位置**完全同一个目录**，
点进去就能看到所有存过的图（`index.json` 是索引，其余是图片本体）。

**Q：左侧对话名字会自己变？**
会。每次你发消息后，会话名会按**你最后问的那句话**重新提炼（约 10 个字），
方便在列表里一眼找到这段对话。如果你手动改过名，就不会再被自动覆盖了。

**Q：C 盘空间紧张**
镜像本身约 7 GB（CPU 版应用 + CUDA 版应用 + Ollama 运行时）。模型没有打进镜像，而是挂载的，所以不会再占 19 GB。

**Q：模型有时「思考到一半就停住」，什么都没回答**
这是**输出长度配额被思考吃光**导致的，不是模型坏了。
Qwen3-VL 无法关闭思考（实测 `think=false`、`/no_think`、提示词引导均无效），
思考本身消耗大量 token；配额给少了，思考用完就没额度写正文了。

现在有两层防护：
1. 默认输出配额从 2048 提到 **4096**（够「想完 + 写完」）
2. 主流程会读 Ollama 的 `done_reason`——若为 `length`（撞上配额被截断），
   **自动加倍配额重试一次**，并在界面提示「正在以更长的配额重试」

另外上下文窗口从 8192 提到 **12288**：工具定义 + 系统提示本身就占约 5000 token，
8192 只剩 3000 给历史与思考，太紧。显存小的机器会自动降级到 CPU，只是慢一些。

**Q：回答中途卡住，感觉模型重新加载了一次**
已修复。原因是 **`num_ctx`（上下文窗口）在不同调用里不一致**：
聊天用 8192、后台自动记忆用 4096。Ollama 只要发现与当前已加载的不同，
就会**卸载并重载模型（约 5 秒），而重载会中断正在进行的生成**。

现在已在客户端层强制统一：**所有模型调用都用同一个 `num_ctx`**，
新增任何调用点也不会再造成重载。

**Q：问天气，它却说搜不到 / 只给了几个天气网站的链接**
早期版本确实如此——天气走的是网页搜索，而搜索引擎对天气查询只会返回
「XX天气预报_15天」这类**网站导航页**，拿不到任何温度数值。
现在天气改走专用数据源，直接返回气温、天气现象等结构化数据，多日预报也支持。
若仍出现异常，多半是**没开界面顶部的「联网」开关**。

**Q：天气数据是哪来的？准不准？**
用的是**中国气象局的数据**（经高德地图转发）：实况是**气象站观测值**、
预报是气象台的产品，和你在国内天气 App 上看到的是同一套。
回答里会写明「数据源」和**观测时间**，可以对着窗外核对。
之前用的是 Open-Meteo（全球模式），实测它在国内**降水虚报很严重**
（同一时刻 10 个城市对比：把晴天说成"毛毛雨"的情况有 37%，而且中文城市名解析也弱），
**现在已经完全不用它了**。

⚠️ 用之前要知道的四件事：
- **必须配高德 key**：天气只走这一家，没 key 就查不了（会提示你去点顶栏的「高德 key」）。
  配一次就行，免费，约 1 分钟。
- **只覆盖中国大陆**：境外的城市查不了（会明说）。中文的境外城市名尤其容易撞上
  国内同名小地方（「东京」「伦敦」在国内都有对应的村镇），所以别指望它查国外天气。
- **港澳台地区暂未覆盖**：高德（中国气象局数据）对中国香港、中国澳门、中国台湾地区
  不提供天气接口，问到时程序会**如实说明是数据未覆盖**（不是"找不到这个地方"）。
- **只有 4 天预报**，而且**没有体感温度、降水概率、降水量**——
  这几项数据源本身就不提供，程序会明确标注「数据源不提供」，**不会给你编一个数**。

💡 **问「明天/后天」也照样准**：结果里每条预报都带日期和「今天/明天/后天·周几」的标注，
表头还会写明今天是几号，所以问哪一天都能对上号（不用担心它把明天说成今天）。

**Q：来源链接为什么不在回答里了？**
现在链接挪到了回答下方的 **「📚 检索来源（N）」** 面板，点击标题即可展开/收起。
这样回答正文不会被一长串 URL 淹没，而且**链接由后端直接给出**，
不是模型转抄的，不会出现抄错或漏抄。面板里标「已精读」的条目，
表示该页正文已被抓取并参与分析。

**Q：联网回答怎么变长了 / 会给出自己的看法吗？**
现在的检索会做**深度阅读**：对前几条结果抓取网页正文（不只搜索摘要），
所以模型有足够材料写细节。同时提示词要求它「先总结、再分析、后展开」，
最后单独给一段「几点看法」——**属于模型推断的部分会明确标注是推断**，
与检索到的事实区分开。若材料不足，它会如实说明而不是硬编。

**Q：查某个单位/学校的公开信息，搜出来的都是百科和聚合站**
现在会自动追加**官方站定向检索**：查学校加 `site:edu.cn`、查政府部门加 `site:gov.cn`、
查协会/学会加 `site:org.cn`，返回的基本是官网本身。
**关键词带上机构全称**（如「深圳大学 招生章程」而不是「深大招生」）效果最好。

**Q：聊久了它就"忘记"前面说过的话（比如成语接龙忘了第一轮）**
已修复。原因是**上下文窗口装不下全部历史**，更早的部分被裁掉后模型就真的看不到了。
现在的做法是：裁掉的部分**不直接丢弃，而是压成一段「较早对话摘要」**放进系统提示，
并明确标注"用户问起最开始聊了什么，就依据本段回答"。
实测 45 轮的成语接龙，回头问第一轮仍然能准确答出。
同时把保留的历史从 20 轮放宽到 **40 轮**，磁盘上也不再提前删除早期记录。

**Q：长期记忆会互相覆盖吗？**
不会。旧版本有个隐患：自动提取是**整段替换**，记新的一条会把该分区旧的抹掉。
现在改成**追加 + 去重**（同一句不会重复记，超出上限时丢最早的、保留最近的）。
分区也按信息类型拆开了（身份信息 / 工作背景 / 偏好习惯 / 重要约定 / 当前项目 / 近期动态），
避免不同类型的信息挤在同一个文段里互相覆盖。

**Q：怎么知道哪块占内存 / 怎么释放？**
侧边栏「🧠 记忆库」下方有 **💾 内存占用**，点开可以看到：

| 项 | 说明 |
|---|---|
| 对话记录 | 各对话的条数、大小、约多少 token；可**单独释放**某个对话 |
| 归档底稿 | 用于"你还记得吗"检索的原始记录，释放前会先沉淀要点 |
| 🧩 长期记忆 | 身份/偏好/约定，**所有对话共享**，**始终保留** |
| 💬 短期记忆 | 各对话的当前上下文，**可以释放** |

「🧹 一键释放」清理归档与对话记录；「🧠 释放短期记忆」只清各对话的短期记忆。
两者都会**先把归档里的要点沉淀进记忆再清除**，不会"释放完就忘事"。

## 七点七、知识库（导入资料 → 模型自主检索）

### 怎么用

1. 侧边栏找到 **📚 知识库** 面板，点 **「📂 打开文件夹」** 直接打开知识库目录
   （面板里也会把完整路径显示出来，源码方式运行时是项目的 `data/kb/`）
2. 把资料文件直接**拷进去** —— **不需要任何导入操作**，检索时会自动扫描到
   （以 `_` 开头的文件会被忽略）
3. 回到界面刷新一下，就能在面板里看到已收录的文档
4. 打开界面顶部的 **「知识库」开关**
5. 之后提问涉及这些资料时，模型会**自己去查**

### 可以建子文件夹分类放

**支持多层子文件夹**，按课程、按项目、按章节分门别类放都行：

```
data\kb\
├── 民航概论\
│   ├── 第一章\讲义.pdf
│   └── 第二章\讲义.pdf
├── 实训守则.md
└── 参考资料\表格\成绩汇总.xlsx
```

- 侧边栏面板会**按文件夹分组显示**（像资源管理器），顺序按「第一章 → 第二章 → 第十章」的自然顺序排
- **模型也看得见这个结构**：它列目录时拿到的是分组的树形清单，
  检索结果里会带上完整路径（如 `民航概论/第一章/讲义.pdf`），回答时能说清"出自哪一篇"
- **子文件夹里的同名文件不会互相覆盖**（`第一章/讲义.pdf` 和 `第二章/讲义.pdf` 各算各的）
- 往子文件夹里放文件：在面板里直接拷，或者拖拽/上传时文件名带上路径（如 `课程A/第一章/笔记.md`）

> ⚠️ 知识库始终是**只读**的 —— 模型只能查、不能改。它自己的产出请放「生成文库」。

### 支持哪些格式

| 格式 | 支持 | 说明 |
|---|---|---|
| `.txt` `.md` `.csv` `.json` `.log` 及各种代码文件 | ✅ | 自动识别 utf-8 / gbk / gb18030 / utf-16 |
| `.pdf` | ✅ | 扫描件（图片版）读不出文字，会明确提示改用图片 |
| `.docx` `.xlsx` `.pptx` | ✅ | 用标准库解析，不依赖额外组件 |
| **`.xls` `.et`（旧版 Excel / WPS 表格）** | ✅ | 自己解析 OLE 复合文档 + BIFF 记录，**连数字都能读出来** |
| `.doc` `.wps` `.ppt` `.dps`（旧版文字/演示） | ❌ | 面板里会显示**具体原因**；用 WPS/Office「另存为」`.docx`/`.pptx` 或 `.pdf` 即可 |

#### 表格是怎么读的

表格会**按行列还原成制表符分隔的文本**，例如：

```
[实训成绩]
姓名	专业	实训成绩
陈宇桐	人工智能技术应用	96
李四	民航运输	81.5
```

- 按单元格引用（如 `C2`）定位列 —— **空单元格不会导致整行错位**
- 工作表名取真实名称（不是"工作表1"）
- 数字格式正确（`96` 不会变成 `96.0`）

> **面板会如实标注每份文档的状态**（`2.4k 字 · 可检索` 或 `读不出文字 + 原因`），
> 不会出现"文件明明放进去了，界面上却什么都没有"的情况。

### 模型是怎么"自主"用它的

两层机制配合，兼顾可靠与自主：

| 机制 | 何时发生 | 作用 |
|---|---|---|
| **自动检索** | 每轮提问都会按相关度搜一次，**只有真命中才注入** | 常见问题不用模型操心，直接就带上了资料 |
| **search_knowledge 工具** | 模型自己决定调用 | 想先看目录（`list_all`）、换关键词多查几轮、或需要更多细节时 |

无关提问的相关度是 **0**，`search` 会直接返回空 —— 所以"自动检索"不会平白占用上下文。

### 与联网的分工

- **知识库优先**：用户自己的资料比网上搜到的更贴合其领域，两者冲突时以知识库为准
- **联网补时效**：需要最新信息时可以两者**同时用**
- 用户没指定时，**由模型自己判断**要不要查知识库、要不要搭配联网
  （「知识库」开关关着的话，模型连这个工具都看不到，自然不会去翻资料）

## 七点九、把文档直接拖给模型（不用先入知识库）

**把文件拖到窗口里任何一个位置都行**，不用非得对准聊天框 ——
拖进来时整个窗口会浮出一层提示（"松开鼠标即可导入"），松手就导入了。
侧边栏、顶部、页面空白处都算拖放区。

- 拖进来后显示一张附件卡片（图标 + 文件名 + 字数），随消息一起发给模型
- 模型会**直接依据文档内容回答**，不需要你先把它放进知识库
- 抽不出文字时（例如旧版 `.doc`/`.wps`）会**明确告诉你原因**，不会静默失败

**输入框左边的 📎 按钮**是走文件选择框的另一条路，效果完全一样。
（拖放依赖宿主窗口把事件交给网页，万一哪天被系统拦住，用按钮一定行。）

**复制文件后按 Ctrl+V 粘贴**也能导入，截图后直接 Ctrl+V 同样可以。

> **拖了没反应？** 现在不会发生了 —— 任何非图片文件都会被当作文档处理，
> 能不能读由后端判断并如实反馈。（旧版本对扩展名做了白名单，
> 名单外的文件会被**静默丢掉**，看起来就像功能坏了。
> 另外旧版本只把聊天区当拖放区，拖到侧边栏是真的完全没有反应。）

**什么时候拖、什么时候放知识库？**

| | 适用场景 |
|---|---|
| **拖进聊天框** | 临时看一份文档、问几处具体内容，用完即走 |
| **放进知识库** | 长期要用、反复查的资料（模型会自主检索，还能跨对话复用） |

两者用的是同一套解析逻辑，效果一致。

## 七点十、随时终止正在生成的任务

发送消息后，**「发送」左边会出现一个红色的「■ 终止」按钮**，点它就能立刻停下：

- 已经生成出来的内容会**保留**在对话里，末尾标注「〔已终止〕」——不会白等
- 模型会**真的停止生成**（不是只把界面停掉），不再占用显卡
- 界面立刻恢复可用，可以马上发下一条

> 实现上，前端会断开连接、后端随即掐掉到 Ollama 的上游连接，
> 所以模型那边也会同步停下，不会在后台空转。

## 七点八、多工具并行

模型**可以在同一条回复里同时发起多个工具调用**，它们会被**并行执行** ——
总耗时只取决于最慢的那个，而不是相加。

实测：6 个工具并行总耗时 0.99s，正好等于最慢单个工具（天气查询）的耗时。

- 彼此不依赖的任务（查知识库 + 联网搜索 + 看时间）会在同一轮一起发出
- 只有参数依赖上一个工具结果时，才分轮调用
- 界面上会显示「⚡ 并行执行 N 个工具」

### 哪些工具受哪个开关控制

| 工具 | 受「联网」开关 | 受「知识库」开关 | 说明 |
|---|---|---|---|
| `generate_image` / `edit_image` | ❌ 不受影响 | ❌ | **本地推理，始终可用** —— 关着联网也能画图 |
| `web_search` / `web_image_search` | ✅ | ❌ | 走外网，关着就连工具都看不到 |
| `get_weather` | ✅ | ❌ | 用数据 API 查真实数值 |
| `search_knowledge` | ❌ | ✅ | 关着知识库就不暴露 |

### 联网 + 生成图片能一起做吗

**能。** 实测让模型一次完成「联网搜广州塔照片 + 生成科幻插画」：
它先调 `generate_image` 生成插画，接着调 `web_image_search` 找实景图，
最后把两者一起呈现出来（共产出 4 张图）。

> 注：qwen3-vl 习惯**每轮只发一个工具调用**，所以这两步会落在相邻两轮，
> 而不是同一轮并行。能力上完全可以同时用，只是模型自己安排了先后顺序。

## 七点五、语音唤醒（源码方式运行）

**说「小千小千」或「小千」即可唤醒**，无需点任何按钮：

1. 程序启动后**自动打开麦克风**进入监听（配置项 `voice_auto_start` 可关）
2. 识别到唤醒词 → **窗口自动弹到最前**，并开始收音
3. 说话过程中实时显示识别文本
4. **停顿 2 秒**自动发送；若一直没说话（或内容太短）则**不发送任何消息**，回到监听

  ### 唤醒很灵敏，是有意为之
  
  语音识别把「小千」写成别的同音字太常见了（晓谦／小签／小迁／筱仟…）。
  只认精确的「小千」会频繁"喊了没反应"，所以这里做了**同音归一化 + 单呼即可唤醒**：
  
  - 「小千小千」「小千」都行；
  - 同音字（晓谦、小签、小迁、筱仟…）归一化后照样命中；
  - 代价是偶尔会误唤醒 —— 但误唤醒只是弹个窗口，**漏唤醒才是真麻烦**。
  
  ### 识别用的模型（精度关键）
  
  模型放在 `D:\local-multimodal-models\sherpa-asr\` 下。**同一目录里有多个模型时，
  会优先选用精度更高的那个**，而不是"谁先被扫到用谁"：
  
  | 模型 | 大小 | 说明 |
  |---|---|---|
  | `streaming-zipformer-bilingual-zh-en-2023-02-20` | 约 190 MB | **默认选它**，中英混说也认得准 |
  | `streaming-zipformer-zh-14M-2023-02-23` | 约 77 MB | 更小更快，但精度差一截（中英混说容易听岔） |
  
  实测同一批音频：小模型把整句英文听成「妈呗他的意思的阿布车」，
  换成双语模型后正确识别为「MONDAY TODAY IS …」。
  
  ### 关于"唤醒慢 / 识别内容乱"（已修）
  
  这两件事以前确实存在，原因有三个，都已处理：
  
  1. **前置音频只留了 0.4 秒** → 流式模型还没"热机"就开始判，唤醒要等更多音频。
     现已加长到 **1.0 秒**。
  2. **人声门槛设得偏高** → 正常说话的起音常低于门槛，开头被当成静音丢掉，
     模型从半个字开始认，既慢又容易认错。门槛已下调。
  3. **唤醒词没被剥掉** → 唤醒后模型给的是整段结果，开头仍带着「小千小千」，
     以前会连同指令一起发出去。现在会**自动剥掉开头的唤醒词**。
  
  ### 为什么不常驻跑识别
  
  常驻监听最容易踩的坑：**每 100ms 就跑一次 ASR 解码**，
  持续吃满 CPU 并持有 GIL，会把同时运行的 Web 服务饿死
  （实测接口响应从 30ms 恶化到 **21 秒**）。
  所以待机时**只在检测到人声后才启动识别**，安静时就只算个音量（开销可忽略），
  并保留 1 秒前置音频、避免第一个字被吃掉。

## 七点六、记忆：长期共享 + 短期独立

| | 范围 | 放什么 | 能被释放吗 |
|---|---|---|---|
| 🧩 **长期记忆** | 所有对话共享（全局一份） | **关于你这个人**的：身份、身边的人与事物、偏好、约定、目标和**未来可能的打算** | **不参与任何释放**，只能手动改 |
| 💬 **短期记忆** | 每个对话各一份，互相独立 | 正在做的项目、本次讨论的结论、临时设定 | 可以（单独清 / 全部清） |

**长期记忆只装"关于你"的东西。** 判断标准就一句话：
**这条对了解你、或对你以后要做的事有用吗？** 有用才记。

具体来说：

- ✅ **会记**：你自己（身份/经历/技能/偏好/目标/顾虑）、**你身边的人**（家人/同学/
  老师/同事/导师/学校/公司）、**你身边的东西**（设备/车/宠物/住处/你在做的项目）、
  以及**你未来可能的打算** —— 哪怕只是随口一提、只是问了一嘴。
  · 你问「自考本科怎么样？」，它会记下「**在权衡要不要报考**」这种意向，
    而不只是原话。假设句（「如果我要考…」）同样会记。
- ❌ **不会记**：**一次性查到的结果**（查到的餐厅评分、天气、路线、票价、比分…）、
  **本应用自己的用法说明**（某功能怎么用、文件存哪儿）、寒暄闲聊、客观知识。
  · 比如你问「附近有什么好吃的」，它只会记「**挑餐厅时在意评分**」这条偏好，
    **不会把菜单和评分记一辈子**。

> 想自己改：侧边栏「🧠 记忆库」里可以直接编辑长期记忆的正文，改完即时生效。

这样分的好处：新开对话**也认识你**（长期记忆共享），
但不同对话之间**不会串味**（短期记忆隔离）。

### 记忆是**自动**记的，不用你说"记住"

每轮对话结束后，程序会在后台读一遍**最近几轮**的内容，自己判断哪些值得留下来：

| 会记 | 不会记 |
|---|---|
| 身份背景、经历成果（做过什么项目、拿过什么奖） | 寒暄闲聊、"哈哈""谢谢" |
| 技能工具（会哪些语言、用什么软件） | 一次性的提问（"帮我查天气""这段代码哪错"） |
| 偏好习惯、约定规则 | 临时指令（"再短一点""换个说法"） |
| **目标计划**（想学什么、打算做什么、什么时候做） | 助手自己的话、搜到的资料 |
| **推断出来的意图**（见下） | 纯客观知识提问（"什么是…""…分几类"） |

"值得记"的判断标准是：**这句话三个月后还用得上吗、换个话题还成立吗。**
成立 → 长期记忆；只在当前这件事里成立 → 短期记忆。

### 你没明说的意图，它也会推断并记下来

有些话**只是提问**，但背后有很明确的个人意图 —— 不推断就会漏掉。

> 你问：**「自考本科怎么样？我未来可不可以去考？」**
> 记进长期记忆的是：`（推断）用户在考虑通过自考提升学历，正在权衡要不要报考`

判断规则：问「我能不能 / 值不值得 / 适不适合 / 要不要」→ 他在**权衡**这件事；
问「怎么才能 / 需要什么条件」且说的是自己 → 有**行动意向**；同一话题反复追问 → **长期关注点**。

两条分寸：
- 记的时候**以「（推断）」开头**，你一眼能看出这是推出来的、不是你说的
- **不替你把话说满** —— 你在考虑就记"在考虑"，不会记成"决定要考"

### 目标会跟着进展**自动更新**（不是越记越多）

这是最容易被忽略的一点：记忆**不是只增不改**。
你说过「打算考四级」，后来又说「四级过了」，程序会把原来那条**改写**成新状态，
而不是再记一条 —— 否则档案里会同时留着"打算考"和"已经考完"，模型读到就自相矛盾。

实测（三轮连续对话）：

| 轮次 | 你说的话 | 记忆里的变化 |
|---|---|---|
| 1 | "我之前做过一个树莓派人脸考勤系统，拿了省三等奖；另外我打算明年6月报考网络工程师" | 新增两条：**经历** + **目标（含当前状态）** |
| 2 | "网络工程师那个我已经报上名了，2027年3月开班" | **改写**原来那条目标为新状态，**没有多出一条** |
| 3 | "哈哈今天天气不错" | **什么都没记** |

> 目标长期没进展**不会被删掉**，也不会反复催你 —— 只在话题相关时顺带关心一句。
> 你说"不做了/弄错了"，它才会删掉或改正。

释放时**先沉淀、再清除**：归档（transcript）是提取记忆的原始素材，
直接删会把"还没被记下的重要内容"永久丢掉。所以任何释放动作都会
**先把归档里的要点提炼进记忆，再清理**，不会出现"释放完就忘事"。

> 侧边栏「💾 内存占用」里可看到长期/短期各占多少，
> 并有「一键释放」和「释放短期记忆」两个按钮，都会明确保留长期记忆。
> 记忆内容可以随时查看和手改；不想要自动记，把顶部「自动记忆」开关关掉即可。

### 顺带修掉的一个性能问题：`localhost` 要等 2 秒

源码方式运行时，Ollama 地址原先是 `http://localhost:11434`。
Windows 上 `localhost` 会**先解析到 IPv6 的 `::1`**，而 Ollama 只监听 IPv4，
于是每次连接都要白等一次回退超时 —— **实测 2065ms，换成 `127.0.0.1` 只需 1ms**。
模型调用很频繁，这一项会持续拖慢整个应用。
现在默认值已改为 `127.0.0.1`，并且**配置加载时会把残留的 localhost 自动纠正**，
老配置也一并受益。修复后接口响应从 4200ms 降到 30ms。

## 七点十一、让模型写代码 / 离线计算

这块由**两个独立开关**控制（顶部胶囊按钮），可以只开一个：

| 开关 | 作用 | 默认 |
|---|---|---|
| **代码模型** | 遇到写代码的需求，自动换用专用代码模型 | **开** |
| **本地算代码** | 让模型在本机真跑 Python，把结果算出来 | **关** |

### 为什么要单独一个「代码模型」

默认模型 `qwen3-vl:8b` 是**视觉**模型，写代码时"思考"会失控。实测同一道 LRU 缓存的题：

| 情况 | 结果 |
|---|---|
| 走运时 | 9 秒，代码正确 |
| 不走运时 | **121 秒后正文一个字都没有** —— 思考陷入原地重复（"但是，题目没有说明…"反复刷屏），把输出额度全烧光 |

3 道题只过 1 道，而且**时好时坏**。这不是额度不够，是模型本身不适合写代码。

所以另外准备了一个**代码专用模型**（`qwen2.5-coder:14b`，约 9GB）。
它是**非思考型**的，不会出现上面那种死循环，写代码的质量和速度都好得多。

- **Docker 部署：已经打包在 `models\ollama\` 里了**，开箱即用，**不需要下载**
- **源码方式运行**：跑一次 `ollama pull qwen2.5-coder:14b` 即可（下载一次永久离线可用）
- **自动生效**，不用改任何设置；没有这个模型时会静默用回默认模型，不会报错
- 只对**当前这一轮**生效 —— 下一轮闲聊自动回到视觉模型（模型切换要重新加载，不能一直换来换去）
- 切换时界面会弹一句提示，免得你以为"回复的口吻怎么变了"
- 不想要这个行为，把「代码模型」开关关掉即可

### 「本地算代码」：别再让它心算

开着的时候，模型写完 Python 会**在你电脑上真跑一遍**，用真实输出作答。

> 实测效果：问"2 的 100 次方是多少、1 到 100 的和是多少"，
> 模型调用 `run_python` 后给出 `1267650600228229401496703205376` 和 `5050` ——
> 都是算出来的，不是"看着像"。

> ⚠️ **「跑不完」不等于「代码有问题」**（这条很重要，别被吓到）
>
> 模型自己验证代码时有个**运行时限**：一次性计算默认 **60 秒**
> （想调就改 `config.json` 里的 `run_timeout`，5~600 秒）。
>
> 但**计时器 / 服务器 / 游戏 / 图形界面**这类**本来就要一直跑**的程序，
> 工具里只会跑前几秒做一次「**冒烟测试**」—— 这是**正常的、不是报错**，
> 模型也不会因此去乱改你的代码（它现在会拿到一句明确的提示：
> 「这算不上报错，也不要为了绕过时限去改结构」）。
>
> **这类程序要完整跑，点代码卡片上的 `▶ 运行`** —— 那里**不设时限**，
> 想跑多久跑多久，随时能停（见下一节）。

### 危险操作会**先问你**，不是直接拒绝

模型想删文件、起进程、连网络时，界面会弹一个框：**说明它要做什么 + 把代码原样贴出来**，
你点「允许执行」它才跑，点「拒绝」它就不跑、并去想办法换个写法。

| 会被问到的操作 |
|---|
| 删除文件 / 目录 |
| 启动外部程序（`subprocess` / `os.system`） |
| 改 Windows 注册表 / 系统开关机 |
| 联网（这个模块本来是给"离线计算"用的） |
| 直接调用系统底层接口（`ctypes`）、动态执行字符串（`eval` / `exec`） |

> 弹窗里会把**完整代码**给你看，看不懂就别点允许 —— 点下去是真在你电脑上执行的。

### 代码在前面就能看、能改、能重跑

模型跑过的代码、以及**它写在回答里的代码块**，都会渲染成一张**代码卡片**：

- `✏ 编辑` → 直接改成你要的样子（就是个编辑框，所见即所得）
- `▶ 运行` → 立刻在本机跑，**边跑边出字**（像终端那样），真实输出贴在卡片下面
  · **不设时限** —— 计时器、倒计时、小服务器这类**要一直跑**的程序就靠它；
    想停就再点一次（按钮会变成 `■ 停止`）
  · **程序里要输入？** 运行的时候卡片下方会出现一个**输入框**：
    程序问到「请输入…」时，你在框里打字、回车，内容就送进去了
    （一行对应一次 `input()`）。不用输入的程序那个框不会有影响。
- `💾 存到文库` → 把这段代码存成**能直接运行的源码文件**（.py / .js / .sh…），
  进「生成文库」面板
- `📋 复制` → 拷走

也就是说，模型给的代码你不用再复制到别处去试 —— **改两个字符、点一下运行**就知道对不对。

> **文件名怎么定的**：优先用你在话里点名的那个（说"文件名就叫 stats.py"，
> 存下来就是 `stats.py`）；没点名就取代码里第一个函数/类名（`def merge(...)` → `merge.py`），
> 再不行才用时间戳。后缀按代码块标明的语言给。
>
> 如果你直接说「**写完存到生成文库**」，模型自己没存的话系统会自动替你存一份
> —— 存完界面会有一条提示带上文件名。写作文/报告这类**非代码**内容仍存成 `.md`。

## 七点十二、写作文 / 生成文档（「生成文库」）

### 三个地方各管一段，别搞混

| | 干什么 | 谁能改 |
|---|---|---|
| 📚 **知识库** | **你**放进去的资料，模型查了用它回答 | 模型**只能读，绝不能改** |
| ✍️ **生成文库** | **模型写出来**的文件（作文 / 方案 / 报告 / 代码模块…） | 模型和你都能改、能删 |
| 🗨 **对话框** | 只是让你写一篇 → **直接写在回答里** | — |

**为什么必须分成两个文件夹**：知识库是你的东西，被模型"顺手改一下"是不可接受的；
生成文库是模型自己的产出，本来就该能增能改能删。
靠"这个文件是谁写的"来判断权限，迟早出错 —— **物理分开最省心**。

### 写作流程：先问清楚，再动笔

你只说一句「帮我写一篇关于大学生活的小作文」这种**信息不足**的要求时，
模型会**弹出一个问答框**问你：用在哪、给谁看、要多少字、想突出什么…
（选项可以直接点，也能自己写；不想答就点「跳过，按你的理解写」）。

> 实测：答完 4 个问题后，模型写出了一篇 **1010 字**的作文，而且会结合它记得的
> 你的专业背景来写。**信息够的时候它不会问**，直接动笔。

### 也可以用文件夹归类

生成文库**同样支持子文件夹**，和知识库一样：

- 你说「放到 `作文/议论文` 里」「这堆代码单独建个文件夹」→ 模型就写进对应子文件夹
- 侧边栏面板**按文件夹分组显示**（顺序按自然数字序，`第一章` 在 `第二章` 前）
- 模型自己列目录时看到的是**分组的树形结构**，所以它知道有哪些文件夹、该往哪儿写
- 复制 / 导出 Word / 删除都在**原文件夹里**进行，不用手动搬来搬去

> 模型不会为了"看起来有条理"硬造文件夹 —— 只有几个文件时还是平铺在根目录，
> 文件多了（或你明确要求）才分层。

### 直接生成文件 / 导出

- 你说「**写成文档**」「**给我一个 Python 模块**」「**保存到文件**」→ 模型写进**生成文库**
- 你说「**导出成 Word**」→ 转成 `.docx`
- 侧边栏「✍️ 生成文库」面板里能：查看、**直接编辑并保存**、导出 Word、**复制一份**、
  下载、删除、打开文件夹、**整库备份**

> **「📋 复制」怎么用**：打开一个文件 → 点「📋 复制」→ 弹出的框里已经预填好
> 「原名-副本」，想改名就改、想放子目录就写 `草稿/第二版.md`，直接回车也行。
> 复制完会**自动打开新文件**接着改；原文件一点不受影响。
> 如果输入的名字已经存在，会**明确拒绝**并让你换一个 —— 复制本来是"留后路"的动作，
> 要是允许它静默覆盖，你一输入重名就把那份文件冲了。

> **关于「WPS 格式」**：旧的 `.wps` 是**私有二进制格式**，官方没公开规范、第三方也写不了，
> 硬造一个只会得到打不开的文件 —— 那是骗人。
> 而 **WPS Office 原生支持 `.docx`**（双击就开、能编辑、能另存为 .wps），
> 所以导出的都是 `.docx`。这是既正确又能用的做法。

**导出 Word 之后继续改文本，点「保存」写的仍是原来那个文本文件**（不是那个 `.docx`）——
不会出现"改着改着把导出的 Word 覆盖成纯文本"这种事。新导出的 Word 排在列表最前面。

### 安全设计

- 覆盖写之前**自动备份**到 `_备份/`；删除是**移进 `_回收站/`**，不是真删 —— 能捞回来
  （模型是自动执行的，必须给你留后悔的余地）
- 路径全部收敛：`../`、绝对路径、盘符都会被挡住，模型写不出文库外面去

## 七点十三、地图（找地方 / 规划路线 / 附近有什么）

### 三种用法

| 你说 | 它会做 |
|---|---|
| 「广州塔在哪」「汕头大学到汕头站怎么走」 | 找地点 / 规划路线，**在聊天里画一张地图卡片** |
| 「汕头大学附近有什么吃的」 | 按半径搜周边场所，列出名字 + 距离 + 地址，并在地图上打点 |
| 「走路过去合适吗」 | 给出**驾车 / 步行 / 骑行**三种方式的对比，并告诉你怎么走更合适 |

### 联网 / 离线两种模式

地图**跟着界面顶栏的「联网」开关走**：

- **开着**：地名、路线、周边店铺、底图**全部实时联网查**。
- **关掉**：**一个网络请求都不发**（这条是实测验证过的）。此时只剩一份内置的
  231 条常用地名表可用（城市/机场/车站/高校/景点这类常见名字），
  **地图卡片不显示底图**。

> ⚠️ **地图不占任何本地空间、也不做缓存**（这是刻意的，不是没做）。
> 早先版本会"联网查过的存本地、断网重放"，但它带来的问题更多：
> 缓存一旦出错就表现为"地图整片空白"，还非常难查；而实际上很少真会断网看地图。
> 所以现在：**联网就实时查，离线就明说查不到**，磁盘上不留一个字节的地图数据。

离线时具体能做什么：

| 问什么 | 离线时的结果 |
|---|---|
| 常见地名在哪（汕头大学、广州白云机场…） | ✅ 查得到（内置表） |
| 两地怎么走 | ⚠️ 路网查不到，只给**直线距离 + 方向**，并标明"不是实际道路" |
| 附近有什么吃的 | ❌ 直接说查不了，让你打开「联网」 |
| 地图底图 | ❌ 不显示（联网后自动恢复） |

### 关于「评分」—— 这里没有

**没有评分、没有星级、没有用户评价。** 数据源是 OpenStreetMap（志愿者测绘的开放地图），
它**不提供**评分和评论数据，我们也不会编一个出来。

对每个场所，给出的是一句**「这条记录全不全」**的说明，比如
「记录里基本只有名字和坐标，可能是小摊小店、也可能已经关了，去之前最好先确认」。
这是**数据完整度**的提示，不是口碑分。

### 出行方式建议

你说要走过去，它不会照单全收 —— 会**把三种方式都算一遍**再给建议：

> 19.2 公里，开车明显更省时间，骑车要花好几倍功夫

⚠️ 注意：免费路网服务**只提供驾车路径**，所以「步行 / 骑行」的距离其实是驾车路线的距离、
时间按速度估算（卡片上会标「时间为估算」）。**那不是真实的步行路径。**

### 它做不到的（说清楚免得误会）

**填了高德 key**（见下一节）时，下面这三条基本都能解决。

**只用 OpenStreetMap**（没填 key）时确实做不到：

- **实时路况**：没有。所以它不会说「避开拥堵」「当前畅通」这类话。
- **公交 / 地铁路线**：没有线路数据。最多建议一句「也可以考虑公共交通」，给不出几路车，
  也**不会编**「坐 302 路、票价 2 元」这种具体线路。
- **小店铺覆盖**：OpenStreetMap 在中国的小微店铺**非常稀疏** ——
  实测汕头大学 1.5 公里内只录到 3 家餐厅、便利店 **0 家**。
  「查不到」不等于「没有」。

### 接高德地图（可选，**强烈建议**）

默认走 OpenStreetMap（免 key，但中国本地数据很弱）。
**填一个高德 key 之后，联网模式下的地图能力会有质的变化**：

| | 只有 OpenStreetMap | 填了高德 key |
|---|---|---|
| **地图底图** | 清淡的志愿者图 | **高德中文路网图**（有中文路名、POI 标注） |
| 附近餐厅（汕大 1.5km） | 3 家、**无评分** | **7 家、带真实评分 + 人均消费** |
| 附近便利店 | **0 家** | **11 家** |
| 驾车用时 | 不含路况 | **按实时路况算** |
| 步行 / 骑行 | 拿驾车路网估算 | **真实路径** |
| 公交 / 地铁 | **完全没有** | **线路 + 票价 + 换乘站** |

> **底图怎么切**：联网 + 配了 key 就是高德底图；没配 key 或关掉「联网」就用
> OpenStreetMap。地图卡片左上角有标签，写的就是当前用的是哪家底图。
> 两家的坐标系不一样（高德 GCJ-02 / OSM WGS-84），程序会自动换算，
> 不用你操心 —— 但**别拿两家的坐标互相核对**，差 50~500 米是正常的。
>
> ⚠️ **国外地点没有高德底图**（高德只覆盖中国大陆）——
> 这时会自动改用 OpenStreetMap 的图，位置是准的，只是底图风格会变一下。

**怎么填**（约 1 分钟）：
1. 打开 https://console.amap.com/dev/key/app ，手机号注册 + 个人实名认证
2. 「创建新应用」→ 随便起个名 → 「添加 Key」
3. ⚠️ 服务平台**必须选「Web 服务」**（选成「Web端(JS API)」是另一套 key，用不了）
4. **两种填法，选一个**：
   - **在界面上填**（推荐）：点顶栏的「**高德 key**」按钮 → 粘贴 → 「连接并测试」。
     会当场调一次高德验证，通过了才保存，**立刻生效不用重启**。
   - 或者改 `data/config.json` 的 `"amap_key": ""` 再重启容器。

> 💡 **没填也不会卡住**：第一次在地图相关的问题上用到时，**它会自己弹一个输入框
> 请你填**（填完同样当场验证、立刻生效，同一次对话就直接用高德重查）。
> 不想填直接关掉就行，它会用 OpenStreetMap 继续做事，只是数据弱一些。

### 顶栏那个「高德 key」按钮，几种样子分别是什么意思

| 样子 | 含义 | 点开能做什么 |
|---|---|---|
| **亮起（绿点）** | 已连接，正在用 | 查看 key / **自动验证** / 断开 / 更改 API |
| **变暗 + 红「!」** | 配了但**当前用不了**（key 失效、额度满…） | 面板里会写明原因，可换 key 或先断开 |
| **变暗** | 你**主动断开**了（key 还留着） | 点「连接」即可恢复，**不用重新输入** |
| **变暗** | 还没配过 | 点「填一个 key」 |
| **变暗** | **关掉了顶栏的「联网」开关** | 会提示你"先打开联网"——这不是 key 的问题，是联网关了 |

几个设计上的讲究（都是踩过坑才这么做的）：

- **「断开」不会删掉你的 key**。断开只是"临时不用"，随时点「连接」就回来 ——
  省得每次都要重新复制粘贴。
- **存下的 key 是只读的**，改不了。要换得点旁边的「**更改 API**」：
  填入新的 → **验证成功才会替换**；验证失败则**原来的一个字都不动**，并明确告诉你这点。
- **「自动验证」**：随时点一下，它会立刻真的去调一次高德（不走缓存），
  把"现在到底通不通"直接告诉你。
- 它还会**后台自动盯着**（正常 15 分钟复查一次、异常 1 分钟一次），
  一旦发现 key 失效，界面会弹提示，并且**在对话里也会提醒你**。
- **它跟着顶栏的「联网」开关实时变**：你一关联网，它**立刻**变暗（不用再点它一下）；
  重新打开联网时它会**自动重新校验一次** key，没问题就自己亮回来。
  按钮的配色也和旁边那一排开关**完全一致**，只有状态点（● / !）表示区别。

```json
{
  "ollama_url": "http://host.docker.internal:11434",
  "amap_key": "把32位key填在这里",
  "web_enabled": true
}
```

不填也能用（会自动回退到 OpenStreetMap，只是能力弱）。
离线时**不管有没有 key**，都只用本地缓存、**不发任何网络请求**。

### 隐私

- **不填高德 key 时**：地名、路线、瓦片全走**免 key 的公开服务**
  （Photon / OSRM / OpenStreetMap 瓦片镜像），不经过任何需要账号的服务。
- **填了 key 时**：仅**联网模式**下的地名搜索、周边搜索、路线规划会发给高德服务器
  （这是用高德的必然代价）。**离线模式下不会发**。

⚠️ **地图数据一个字节都不落盘**（2026-09-18 起）：查过的地名、路线、底图瓦片
都**不缓存**，响应带 `no-store`，连浏览器里也不留。所以 `data/` 目录下
**没有 `map_cache/`**（老版本有过，升级后可以手动删掉）。

> ⚠️ **服务只监听本机**（`compose.yml` 里写的是 `127.0.0.1:8000:8000`）。
> 也就是说**同一个 WiFi 下的其他人打不开、也读不到你的东西**。
> 这个前缀别删 —— 只写 `8000:8000` 的话 Docker 会绑到所有网卡，
> 在办公室/酒店的共享网络上，同网段的人不光能浏览你的记忆和会话，
> 还能从接口里读到高德 key。确实需要局域网访问再自己改，但要清楚这意味着什么。

## 八、技术说明（给维护者）

**镜像**：只有一个 `local-multimodal-app:latest`
= python:3.12-slim + 后端 + 前端 + torch/diffusers/spandrel。**不含任何模型权重**。

**路径约定**

| 内容 | 容器内路径 | 来源 |
|---|---|---|
| 后端/前端代码 | `/opt/app` | 镜像内 |
| 运行数据 | `/data` | 挂载 `./data` |
| 对话模型 | `/root/.ollama/models` | 挂载 `./models/ollama`（自带模式） |
| 绘图模型 | `/opt/app/sd_model` | 挂载 `./models/sd-turbo` |
| 超分模型 | `/opt/app/esrgan` | 挂载 `./models/esrgan` |

**应用支持的环境变量**（`backend/config.py`）

| 变量 | 作用 |
|---|---|
| `MM_DATA_DIR` | 可写数据根目录；容器里只需挂一个卷 |
| `MM_OLLAMA_URL` | Ollama 地址（直连 `host.docker.internal:11434` / 自带 `ollama:11434`） |
| `MM_MODEL` | 默认模型名 |
| `SD_MODEL_DIR` | 绘图模型目录 |
| `ESRGAN_MODEL` | 超分模型文件 |

**为什么模型不放镜像里**：模型共 19 GB，打进镜像会与包内 `models\` 重复占用，
并且 Docker 数据盘（默认在 C 盘）会再吃掉 10 GB。挂载方式让模型只存一份。

**重新构建**

```bat
cd build
docker build -f docker/Dockerfile.app -t local-multimodal-app:latest .
docker save local-multimodal-app:latest -o ..\images\local-multimodal-app.tar
```
